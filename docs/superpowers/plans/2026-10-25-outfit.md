# Machine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution or superpowers:subagent-driven-development if the user chooses delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a cross-platform machine management CLI/TUI with software presets, reviewed dotfiles, 1Password integration, and versioned bootstraps at johnhenning.dev/tools/outfit/.

**Architecture:** The `outfit` Go application reads a versioned external configuration bundle from the independent `outfit-profiles` repo, detects a target, and resolves saved selections into an explicit action plan. A separate executor applies that plan through native package managers, chezmoi, and narrowly scoped configuration actions. Interactive and noninteractive entry points share resolution and execution.

**Tech Stack:** Go with C dependencies excluded; Cobra CLI, Bubble Tea TUI with Bubbles/Lip Gloss, YAML manifests, chezmoi, POSIX shell, PowerShell, GitHub Actions. Verify current official documentation and pin compatible stable dependencies during implementation, not floating versions. Native package providers: brew, apt, dnf, winget.

**Repository split:** Runtime/schema/provider code and bootstraps live in `outfit/`; production catalogs, named profiles and chezmoi sources live in `outfit-profiles/`. All task code paths are relative to outfit except catalog/dotfiles/profile data paths, which belong to outfit-profiles. Add strict external-bundle loading and digest verification before catalog resolution; profile URLs use a temporary engine and pin both versions.

**Spec:** `docs/superpowers/specs/2026-10-25-outfit-design.md`

## Global Constraints

- macOS, Debian-family Linux, Fedora-family Linux, native Windows, and WSL.
- uv manages Python versions, environments, and Python tools. Do not install or activate mise in the managed configuration.
- The Unix entry point is `curl -fsSL https://johnhenning.dev/tools/outfit/install.sh | sh`; the Windows entry point is `irm https://johnhenning.dev/tools/outfit/install.ps1 | iex`.
- Leave the root domain available for a personal site.
- Treat all these as planned URLs until deployed and verified.
- Manage explicit allowlisted files only.
- Do not run package installs, service activation, WSL provisioning, or dotfile application on the current workstation merely to test this repo.
- Do not provision a broad personal-vault service token or enable SSH agent forwarding by default.
- Existing email and unrelated DNS records must be preserved.
- Update does not implicitly upgrade every package on the system.
- GitHub destination, repository visibility, hosting access, media-server choice, and GPU stack are delivery inputs, not invented credentials or defaults.

## Review Focus

- Piped bootstrap has no interactive stdin: reconnect to the terminal or fail with a usable noninteractive instruction; Task 9.
- Partial installs and cancelled runs: preserve accurate results, stop dependents, and support safe rerun; Task 4.
- Windows/WSL path and privilege boundaries: native desktop apps and Linux tooling must target their respective environments; Task 7.
- Existing configs, symlinks, and local secrets: do not overwrite unmanaged targets or leak rendered secrets in previews/backups; Task 5.
- A saved plan outlives its config/catalog or is edited: validate action provenance and recheck target state before executing; Tasks 3 and 4.

## File and Interface Map

- `cmd/outfit/main.go`: process entry and exit codes.
- `internal/cli/`: Cobra commands, argument validation, output rendering.
- `internal/platform/`: OS, distro, architecture, desktop/headless and WSL detection.
- `internal/catalog/`: external bundle loading, schema validation and digest verification.
- `internal/selection/`: outfit config persistence, defaults, conflicts and overrides.
- `internal/plan/`: pure action resolution, dependencies, stable plan serialization.
- `internal/execute/`: runner, privilege boundaries, journals and result reporting.
- `internal/provider/`: native package providers and reviewed vendor installers.
- `internal/dotfiles/`: chezmoi preview/apply boundary, conflict checks and backups.
- `internal/credentials/`: 1Password status, guided setup, scoped process execution.
- `internal/windows/`: WSL discovery/provision/resume and cross-environment routing.
- `internal/tui/`: role/preset flow, category choices, Advanced, review and results.
- `catalog/{software,categories,presets,roles}.yaml`: production product data in outfit-profiles.
- `dotfiles/`: reviewed chezmoi source, includes and OS/role templates.
- `bootstrap/install.sh`, `bootstrap/install.ps1`: release launchers.
- `site/tools/machine/`: static documentation and published bootstrap copies.
- `.github/workflows/{ci,release,site}.yml`: validation, releases and site delivery.
- `tests/fixtures/`, `tests/integration/`: synthetic homes/platforms/commands, no real credentials.

Shared types, defined by their owning tasks:

- `platform.Target{OS, Arch, Family, Environment string; Desktop bool}`; Environment is native, wsl, container, or remote. Unknown environments must remain explicit rather than guessed from SSH variables alone.
- `selection.Config{SchemaVersion int; Name, Role string; Presets []string; Packages []string; Exclude []string; Preferred map[string]string; Options map[string]string}`; secret values are not valid options.
- `plan.Action{ID, Kind, Provider, PackageID, Target, Description string; DependsOn []string; Privileged bool; ManualReason string}`; actions refer to registered implementations, never arbitrary shell snippets from saved plans.
- `plan.Plan{SchemaVersion int; Target platform.Target; ConfigDigest, CatalogDigest string; Actions []Action}`.
- `execute.Runner.Run(ctx context.Context, command Command) (Output, error)`; Command contains executable, argument array, target environment and sensitive-input policy. It is never rendered as an executable shell string.
- `execute.Result{ActionID, Status, Message string}`; status is installed, configured, already-present, manual, skipped, failed, or cancelled. Manual or failed work must not appear as fully complete.
