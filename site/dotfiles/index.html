John’s dotfiles

The shell, editor, and terminal setup I take from machine to machine. Shared settings for Zsh and Bash, with room for each project’s tools.

For macOS and Linux on ARM64 or x86-64. On Windows, use WSL.

Install

curl -fsSL https://johnhenning.dev/tools/dotfiles/install.sh | sh

Installs the configuration manager and downloads the repo, then asks for confirmation before backing up and applying configs. Open a new terminal afterward.

Preview changes first

Use --dry-run or --preview to see the config changes without applying them. The manager and source are still downloaded.

curl -fsSL https://johnhenning.dev/tools/dotfiles/install.sh | sh -s -- --dry-run

For an unattended install, use --yes instead. Preview and unattended installation are separate modes.

What’s included

Zsh and Bash
Shared aliases, editor choices, history, uv completion, and direnv hooks. Zsh supports optional Oh My Zsh and Powerlevel10k; Bash has its own simple prompt.
PATH
One shared module with deduplication, local tool fragments, and temporary with_path commands. Project environments stay inside their projects.
tmux
Ctrl-Space prefix, Vim-style pane navigation, vi copy mode, and splits that keep your working directory. Existing Catppuccin and TPM plugin choices are preserved.
Neovim
The preserved NvChad setup, onedark theme, Lua LSP settings, custom mappings, and a 27-plugin lockfile. Plugins download when you first start Neovim.
uv and Git
uv configuration for project-managed Python, plus Git defaults and a local include for your identity and signing preferences. No mise activation.

Finish your terminal setup

Installing configs and installing tools are separate steps. Inspect what’s missing, then choose the pieces you need.

dotfiles doctor
dotfiles tools

Tools

dotfiles tools --apply installs missing shell tools using Homebrew, apt, or dnf, with verified uv and Neovim downloads when needed. macOS requires an existing Homebrew installation.

Optional frameworks

dotfiles plugins previews Oh My Zsh, Powerlevel10k, and TPM setup. Add --apply to install them. Existing checkouts are kept. Choose a Nerd Font for prompt and editor icons.

Your login shell stays unchanged. In tmux, press Ctrl-Space then Shift-I to install its configured plugins. Read the repo notes for editor tools and plugin details.

Keep the setup yours

Global tools, temporary tools, and project tools

Add intentional global tools to ~/.config/shell/path.local.sh, or use separate files in ~/.config/shell/path.d/.

path_prepend "$HOME/.cargo/bin"
path_append "$HOME/tools/some-sdk/bin"

For a single command, leave your current PATH untouched:

with_path "$HOME/tools/special-sdk/bin" special-command --help

Use uv run and uvx for isolated Python tools. For a project-wide environment, review the direnv example, then explicitly run direnv allow. Leaving the directory restores your environment.

Machine settings and private credentials

Keep shared overrides in ~/.config/shell/local.sh, shell-specific settings in ~/.config/zsh/local.zsh or ~/.config/bash/local.bash, and Git identity in ~/.config/git/local.config. These local includes are not replaced by repo updates.

Sign in to 1Password and individual services afterward. The repo contains no keys, tokens, sessions, or private SSH hosts. The macOS SSH agent example is opt-in.

Updates and backups
dotfiles update
dotfiles diff
dotfiles apply

update fetches a fast-forward revision of a clean source checkout and shows the changes. apply asks for confirmation and backs up existing managed files under ~/.local/state/john-dotfiles/backups/ before replacement.

Existing rc files are managed too: review the changes and move settings you want to keep into local includes. Symlink targets require manual review. The layout uses ~/.config; a custom XDG_CONFIG_HOME requires manual setup. See the recovery instructions.
